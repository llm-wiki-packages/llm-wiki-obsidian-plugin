# Review 6 — day two with the one view

Branch `feature/command-center` at da31600; fixture screenshots at 1400x900 and 420 wide. Ranked by how much each changes what the owner does next.

## 1. A plain click on a search hit or a reply wikilink replaces the view (Search, Chat)

Evidence: `src/views/search.ts:103` and `src/ui/links.ts:27` call `openLinkText(path, '', metaKey || ctrlKey)`; the Ingest row (`src/views/dashboard/index.ts:274`) passes `true`. In a main-area tab, `false` means "the active leaf", which is the dashboard itself. Day two: the owner clicks the page a reply names, and the view, the transcript and any running turn (`onunload` aborts it) are gone; Continue last chat recovers Agent, nothing recovers Ask. Ingest rows survive the same click.

Fix: inside the view every note opens with `'tab'`; modifier-click opens a split. One line in two files, and the biggest blocker to the one-view decision being right. Confirm in Obsidian first.

## 2. (a) One view is right; where it lives should be the owner's choice

What the tab lost: dashboard and chat never visible together; chatting beside the note you read. The chips are only half lost: `getActiveFile()` returns the last file view, so the note chips name the note you just left, which is right more often than not.

Recommendation: keep the one view (two chat surfaces would mean two session states). Add one affordance, not a second surface: a gear-menu item "Move to the right sidebar" / "Move to the main area", remembered. That makes the narrow layout (finding 4) first-class, because the sidebar is where chat-beside-a-note happens. Do not re-add a sidebar chat pane; do not auto-split on open.

## 3. (c) Ingest: the loop from a run to its pages is not closed

Screens: Overview "Last day" says "Scheduled pass · 2 pages written"; Ingest shows drafts under "WEB/ACME · 2". After pressing Run a person expects "the pages this run landed, under the job's name". The row and the group never meet: the Last-day row opens the job dialog, and the group is a folder in small caps, not "Acme engineering blog".

Fixes: group drafts by job name with the folder as the detail line; a "2 pages written" row goes to Ingest with that group expanded; the Overview button that leads here says "Ingest", not "Review" (two names, one tab). Drop the "1 ·", "2 ·" numbers: two sections and the pipeline sentence already carry the order. "Ingest" is a fine name.

## 4. (e) Narrow: the tabs that justify a sidebar are the ones cut off

Evidence `/tmp/c6-chat-narrow.png`, `/tmp/c6-overview-narrow.png`: the tab bar clips at "Se…", so Search and Chat cannot be clicked; Refresh and the gear wrap to a centered line of their own; "YouTube subscriptions stopped: yt-cookies is stale" wraps to four lines beside two buttons; the permission command breaks mid-word (`--jso` / `n`).

Fix: a width class set by a ResizeObserver on the view (under ~600px): row actions stack under the text; Refresh is icon-only; the left five tabs collapse into one "Manage" dropdown so Search and Chat stay visible; `word-break: break-word` on the permission summary. Do this before offering the sidebar move.

## 5. (d) Credentials tab: right, with two stale claims to clean

It no longer duplicates Skills: `src/views/dashboard/skills.ts` has three sections and no credentials group, while `docs/ux.md` and the README still say Skills ends with Credentials — delete those paragraphs. "Needed by an enabled skill" is the right second section: inventory first, then the one to-do it implies, with the same button the Overview shows. Keep it below.

## 6. (b) Tab order and the header

The split is right: manage left, talk right. The left order is setup order, not day-two order: Credentials is visited once, Ingest daily. Recommend Overview, Ingest, Jobs, Skills, Credentials. The pill as a button with a tooltip is good; "refreshed 09:51 PM" is quiet and true. Keep the gear; demote Refresh to an icon.

## 7. Wording that leaks the implementation

- "jail": Credentials note ("inside its own jail"), Ask capability line ("read-only, jailed") → "apart from the vault" / "read-only; each question starts fresh".
- "ticket": Overview row detail for a parked or review ticket (`snapshot.ts:449,454` put `ticket <id>` on screen), tool rows "Reading the ticket list" / "Retrying ticket", job dialog "no ticket records remain". Say "run"; ids stay on hover.
- "sandbox", "skill stage": tool rows "Binding a skill stage to its sandbox", "Enabling the X sandbox"; settings "Ask mode sandbox" → "read-only profile".
- "harness": settings "each harness's default", "harness stderr line" → "each mode's default", "chat process output".
- `snapshot` and `nono` never reach the screen.

## Running / due / needs you

Running, due, held and queued all come from `jobs ls` running[], the verdict and `tickets ls` (`snapshot.ts:266-300`); the health sentence and cards read the same JobView. Nothing invents a state. One drift: "held" compares `not_before` with the client clock, so a skewed Mac shows Queued where the CLI says held; prefer the verdict when it carries one.

## (f) Three to do, three to resist

Do: 1 (open in a new tab), 4 (narrow layout, then the move-to-sidebar item), 3 (run → its pages). Ask-mode memory stays the known gap and outweighs every cosmetic item.

Resist: a second chat surface; more tabs (logs, history); ids, folders or commands where a name fits; auto-splitting the workspace on open; filters on Search before anyone asks.
